# BUG-002 — `infra/bin/app.ts` importa módulo inexistente na árvore commitada (build quebrado)

## Status
VALIDADO

## Severidade
CRÍTICA

## Prioridade sugerida
P0

## Origem
- SPEC_ID: 002-extracao-dados-orcamento
- Requisito: T004 — provisionar regra EventBridge `OrcamentoClassificado` → `extrator-queue`
- Critério de aceite: `typecheck:infra` e `cdk synth` executáveis a partir de um checkout limpo do branch/commit
- Tarefa: T004
- Ambiente: local (worktree limpo, sem arquivos untracked), Node 18.19.1
- Commit ou versão: `5ecb355` (branch `feat/002-t004-eventbridge-rule-extrator-queue`, PR #420)

## Resumo
O commit `5ecb355` altera `infra/bin/app.ts` adicionando `import { ValidadorQueueStack } from '../lib/validador-queue-stack.ts'` e a instanciação `new ValidadorQueueStack(...)`. Esse arquivo (`infra/lib/validador-queue-stack.ts`) **não existe em nenhum commit do branch** — pertence a um branch irmão não mergeado (`feat/003-t003-validador-queue`, commit `3f14041`, spec 003, fora do escopo da T004). O import só resolve localmente porque o arquivo existe *untracked* no working tree da máquina de desenvolvimento (outro agente trabalhando em paralelo na mesma pasta). Qualquer checkout limpo deste commit — inclusive CI — falha em `typecheck:infra` e em `cdk synth` para **todos** os stacks, não apenas `ExtratorQueueStack`.

## Pré-condições
Checkout do commit `5ecb355` isolado (sem o arquivo untracked `infra/lib/validador-queue-stack.ts` presente no working tree).

## Passos para reproduzir
```bash
git worktree add /tmp/qa-clean 5ecb355
cd /tmp/qa-clean
ln -s /Users/paulolopes/Documents/Labsit/nexus-orc-back/node_modules node_modules   # reuso de deps já instaladas
npm run typecheck:infra
```

## Resultado atual
```
infra/bin/app.ts(8,37): error TS2307: Cannot find module '../lib/validador-queue-stack.ts' or its corresponding type declarations.
```
`cdk synth --app "npx tsx infra/bin/app.ts" ExtratorQueueStack` falha de forma equivalente, em runtime:
```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../infra/lib/validador-queue-stack.ts' imported from '.../infra/bin/app.ts'
```

## Resultado esperado
`typecheck:infra` e `cdk synth` passam a partir de um checkout limpo do commit da PR, sem depender de arquivos de outro branch presentes por acaso no working tree local.

## Evidências
- Comando: `git worktree add`, `npm run typecheck:infra` — saída acima (worktree isolado, sem arquivo untracked).
- `git ls-tree -r 5ecb355 --name-only | grep validador` → vazio (arquivo não está na árvore do commit).
- `git log --all --oneline -- infra/lib/validador-queue-stack.ts` → único commit é `3f14041` no branch `feat/003-t003-validador-queue`, não ancestral de `5ecb355` (`git merge-base --is-ancestor 3f14041 5ecb355` → não).
- No worktree principal (com o arquivo untracked presente), `typecheck:infra`/`eslint` passam silenciosamente — reproduz o falso positivo que levou à validação prévia do dev-back-end.

## Frequência
SEMPRE, em qualquer ambiente que não tenha o arquivo untracked por coincidência (CI, outro desenvolvedor, outro worktree).

## Impacto
Bloqueia CI/build de todo o app CDK (todos os stacks, incluindo `ClassificadorQueueStack`, `DominioEventBusStack` etc.), não apenas o escopo da T004. Se mergeado como está, quebra a main.

## Hipótese técnica
`infra/bin/app.ts` é compartilhado por múltiplas specs/tasks. Outro agente trabalhava em paralelo na spec 003 no mesmo arquivo, no mesmo working tree/máquina, com `infra/lib/validador-queue-stack.ts` criado mas não commitado. O commit `5ecb355` da T004 capturou as edições concorrentes desse arquivo compartilhado (import + instanciação do `ValidadorQueueStack`) sem incluir o arquivo novo correspondente — escopo cruzado, não intencional.

## Escopo de regressão sugerido
Após a correção, reexecutar: `npm run typecheck:infra`, `npx eslint infra/`, `npx cdk synth --app "npx tsx infra/bin/app.ts"` (todos os stacks) em worktree limpo — não apenas no working tree local do desenvolvedor.
