# BUG-001 — `ExtracaoOrcamento.historico` getter expõe array interno mutável

## Status
PRONTO PARA RETESTE (corrigido no commit `6fcb0bc`, cópia defensiva `[...this._historico]` + teste unitário adicionado — cabe ao QA validar)

## Severidade
BAIXA

## Prioridade sugerida
P3

## Origem
- SPEC_ID: 002-extracao-dados-orcamento
- Requisito: critério de aceite "histórico nunca é apagado, apenas anexado" (spec.md, Preservação do vínculo / T009 / T035)
- Critério de aceite: append-only do histórico de tentativas
- Tarefa: T009
- Ambiente: local (leitura de código, sem necessidade de execução)
- Commit ou versão: 82bb32b152fc2bee2a3133414d4aa0ae0ec9c1db

## Resumo
`ExtracaoOrcamento.historico` (getter, `extracao-orcamento.aggregate.ts:123`) retorna
`this._historico` diretamente, sem cópia defensiva. Qualquer código que consuma o
agregado pode fazer `extracao.historico.push(...)` ou `.length = 0` e alterar o
histórico por fora dos métodos do agregado, violando o invariante "append-only,
histórico nunca é apagado".

O mesmo padrão de bug (referência interna vazando via getter) foi identificado e
corrigido no próprio commit 82bb32b para o getter `itens` e para as atribuições
internas de `_itens` em `registrarTentativaExtrator`/`registrarConfirmacaoHumana`
— o getter `historico` não recebeu a mesma correção.

## Pré-condições
Nenhuma — basta ter uma instância de `ExtracaoOrcamento`.

## Passos para reproduzir
1. `const extracao = ExtracaoOrcamento.criar(...)`
2. `extracao.registrarTentativaExtrator(itensCompletos, condicoesCompletas)` (gera 1 entrada de histórico)
3. `extracao.historico.length = 0` (ou `.push(...)`, ou `.pop()`)
4. `extracao.historico` agora reflete a mutação externa — o histórico foi apagado/alterado sem passar por nenhum método do agregado.

## Resultado atual
`extracao.historico` é a mesma referência de array usada internamente (`this._historico`); mutável de fora do agregado.

## Resultado esperado
`extracao.historico` deveria retornar uma cópia (`[...this._historico]`), como já feito no getter `itens`, tornando o array interno inacessível para mutação externa.

## Evidências
- Leitura de código: `src/bounded-contexts/extracao/domain/extracao-orcamento.aggregate.ts:123-125`.
- Comparação com o fix já aplicado no getter `itens` no mesmo arquivo (commit 82bb32b).
- Nenhum teste automatizado cobre esse cenário hoje (ausência de teste, não falha de teste existente).

## Frequência
SEMPRE (estrutural — qualquer chamador que obtenha a referência pode mutar).

## Impacto
Nesta leva (Domain isolado, sem Application/Infrastructure/Interface expondo o
agregado a chamadores externos), não há nenhum consumidor real do getter ainda —
impacto atual é zero em produção. Risco passa a existir a partir do momento em
que Application/Infrastructure (T012+) começarem a ler `historico` para persistência
ou serialização, onde uma mutação acidental (ex.: um mapeamento que reordena/filtra
o array recebido) corromperia o estado interno do agregado sem lançar nenhum erro.

## Frequência
SEMPRE

## Hipótese técnica
Nit de encapsulamento não replicado para o getter `historico` quando o mesmo padrão
foi corrigido para `itens` no commit 82bb32b (aparenta ter sido um esquecimento,
não uma decisão deliberada — não há comentário ou teste indicando exceção intencional).

## Escopo de regressão sugerido
Nenhum — é aditivo (cópia defensiva), não deveria quebrar nenhum teste existente.
Ao corrigir, adicionar 1 teste unitário equivalente ao que valeria a pena existir
para `itens` (mutar o array retornado por `.historico` e confirmar que o estado
interno do agregado não muda).
