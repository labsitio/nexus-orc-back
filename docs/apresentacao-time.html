Nexo: do briefing à stack, para quem vai construir

Nexo é uma plataforma de dados para redes varejistas, construída do zero para rodar 100% na AWS. Ela recebe orçamentos de fornecedores — cotações de produtos para venda, com itens, preços e condições — por 4 canais — upload via portal web, API REST, SFTP e aplicativo mobile — e processa cada um automaticamente com agentes de IA: identifica o fornecedor e o formato do orçamento, extrai os dados estruturados, valida consistência, organiza e indexa o conteúdo e deixa tudo pronto e pesquisável para o time de compras. Este documento detalha componentes, stack, agentes, fluxo, segurança e escalabilidade para quem vai implementar, com desenvolvimento orientado por agentes de IA.

01 · Componentes

Os 9 componentes centrais do sistema

Cada componente tem uma responsabilidade única e se comunica com os demais por eventos — nenhum deles conhece a implementação interna do outro.

Gateway de Ingestão

Ponto único de entrada para os 4 canais de recebimento de orçamentos de fornecedores. Normaliza o recebimento e grava o orçamento bruto no S3 antes de qualquer processamento.

  • Upload via portal web — API Gateway + URL pré-assinada do S3
  • API REST — API Gateway, para integração direta de sistemas parceiros
  • SFTP — AWS Transfer Family, para parceiros que só integram por transferência de arquivo
  • Aplicativo mobile — app nativo autenticado via Cognito, upload direto para S3 via API, com notificação push de status

Barramento de Eventos

Publica e distribui eventos de domínio — orçamento recebido, fornecedor/formato identificado, extraído, validado, indexado. Desacopla os agentes entre si: cada um reage a eventos, sem chamadas diretas aos demais.

Orquestrador de Workflow

Define a sequência de agentes para cada orçamento recebido, trata falhas com retentativa automática e decide o próximo passo do fluxo — incluindo quando encaminhar para o comprador responsável ou acionar uma integração externa.

Agentes de IA (5 especializados)

Conjunto de agentes rodando sobre Amazon Bedrock que identifica fornecedor e formato, extrai, valida, indexa e decide o roteamento de cada orçamento. Detalhamento completo de cada agente na seção 4.

Camada de Dados

Guarda o orçamento bruto, os itens e condições extraídos e estruturados, e os metadados de cada etapa do processamento — com histórico completo de versões e vínculo entre origem e resultado.

Camada de Busca

Índice semântico e textual sobre todo o acervo processado, permitindo consulta em linguagem natural — "orçamentos de embalagens recebidos abaixo de R$10 mil nos últimos 30 dias" — e não apenas busca por campo exato.

Portal & API

Camada de acesso para usuários internos e integrações de sistemas parceiros — contratos de API versionados, autenticação própria e visão de status de cada orçamento em processamento.

Portal Web de Acompanhamento (Painel do Gestor)

Interface web (React/Next.js, autenticação Cognito, hospedada em CloudFront + S3) onde o gestor da rede varejista acompanha o ciclo de vida completo de cada documento: canal de entrada, timestamp de cada etapa do pipeline (recebido → classificado → extraído → validado → indexado → disponível/arquivado), status atual, alertas de erro ou pendência, busca e filtros por período/tipo/remetente, e exportação de relatórios de auditoria. Consome os mesmos eventos do EventBridge e a trilha do CloudTrail; dados de status agregados ficam no Aurora.

Camada de Observabilidade

Métricas, tracing distribuído e logs correlacionados por identificador de orçamento — permite reconstruir, passo a passo, o que aconteceu com qualquer arquivo do início ao fim.

03 · Agentes de IA envolvidos

5 agentes especializados, rodando sobre Amazon Bedrock

Cada agente tem entrada, saída e responsabilidade bem definidas. Eles se comunicam através do barramento de eventos e são orquestrados pelo Step Functions.

Agente 1

Classificador de Fornecedor e Formato

Identifica automaticamente o fornecedor que enviou o orçamento e o formato/layout utilizado — cada fornecedor manda de um jeito diferente (PDF, planilha, e-mail, formulário próprio, catálogo), sem padrão — antes de qualquer extração.

Entrada
Orçamento bruto (S3) + metadados de origem
Saída
Fornecedor e formato identificados + nível de confiança
Agente 2

Extrator de Dados

Combina Amazon Textract com o modelo de linguagem para extrair campos estruturados do orçamento — itens, SKU/descrição do produto, quantidade, preço unitário, condições de pagamento, prazo de validade da proposta e condições de entrega — a partir do formato real usado pelo fornecedor.

Entrada
Orçamento com fornecedor/formato identificados + saída do Textract
Saída
JSON estruturado por item, com preços e condições comerciais
Agente 3

Validador de Consistência

Aplica regras de negócio sobre os dados extraídos — CNPJ do fornecedor válido e batendo com o cadastro, campos obrigatórios preenchidos, preços dentro de faixas esperadas, prazo de validade coerente — e sinaliza divergências para revisão.

Entrada
Dados estruturados do Agente 2
Saída
Status de validação + lista de inconsistências
Agente 4

Indexação e Busca Semântica

Gera embeddings do conteúdo do orçamento e dos itens extraídos, gravando no banco vetorial para habilitar busca semântica sobre todos os orçamentos recebidos.

Entrada
Orçamento validado + dados estruturados
Saída
Vetores de embedding indexados
Agente 5

Orquestrador de Workflow

Decide o próximo passo com base no resultado dos demais agentes — aprovar automaticamente, encaminhar para o comprador responsável avaliar, ou solicitar reenvio ao fornecedor quando faltar algum dado — e mantém o registro de decisão para auditoria.

Entrada
Saída consolidada dos agentes 1 a 4
Saída
Próxima ação do workflow + evento de decisão
04 · Fluxo completo de processamento

Do documento chegando até virar dado pesquisável

Explicação passo a passo do caminho de um documento pelos componentes descritos acima. O diagrama visual detalhado está no arquivo de arquitetura macro.

  1. Recebimento no Gateway de Ingestão

    O orçamento chega por um dos 4 canais — upload via portal web, API REST, SFTP ou aplicativo mobile — e é gravado no armazenamento bruto (S3). Um evento de "orçamento recebido" é publicado no barramento.

    API Gateway + AWS Transfer Family + Cognito → S3 → EventBridge

  2. Disparo do workflow

    O Orquestrador de Workflow (Step Functions) consome o evento e inicia a execução, chamando o Agente Classificador como primeira etapa.

    EventBridge → Step Functions

  3. Identificação do fornecedor e do formato

    O Agente Classificador identifica o fornecedor que enviou o orçamento e o formato/layout utilizado — cada fornecedor manda de um jeito diferente, sem padrão — e publica o resultado com o nível de confiança.

    Bedrock (Claude) → EventBridge

  4. Extração estruturada

    Amazon Textract processa o orçamento para extrair texto, tabelas e formulários; o Agente Extrator organiza esse resultado em itens, preços, quantidades e condições comerciais estruturadas.

    Textract + Bedrock → dados estruturados

  5. Validação de consistência

    O Agente Validador confere os dados extraídos — preços, campos obrigatórios, dados do fornecedor — contra regras de negócio. Inconsistências geram um evento de exceção e podem acionar fila de revisão humana.

    SQS (fila de exceções) → revisão, se necessário

  6. Persistência na camada de dados

    Dados validados são gravados no Aurora Serverless v2; o orçamento original permanece no S3 com sua trilha de versões.

    Aurora Serverless v2 + S3

  7. Indexação semântica

    O Agente de Indexação gera embeddings do conteúdo e grava no banco vetorial (pgvector ou OpenSearch Serverless), tornando o orçamento pesquisável por linguagem natural.

    pgvector / OpenSearch Serverless

  8. Decisão de próximo passo e integrações

    O Agente Orquestrador decide a ação final — aprovar automaticamente, encaminhar para o comprador responsável ou solicitar reenvio ao fornecedor — e o Portal/API expõe o status atualizado do orçamento.

    Step Functions → integrações externas / Portal

  9. Observabilidade contínua

    Cada etapa acima gera métricas e spans de tracing correlacionados pelo identificador do documento, disponíveis via CloudWatch, X-Ray e OpenTelemetry durante todo o processo.

    CloudWatch + X-Ray + OpenTelemetry

  10. Acompanhamento pelo gestor

    Em paralelo a todas as etapas acima, o gestor da rede varejista acompanha o status de cada documento pelo Portal Web de Acompanhamento — canal de entrada, timestamp de cada etapa do pipeline e alertas de pendência, em tempo real.

    EventBridge + CloudTrail → Portal do Gestor

05 · Segurança

Segurança e conformidade desde o desenho

Orçamentos de fornecedores contêm dado comercial sensível — preços, condições comerciais e dados de contato — a segurança é tratada como requisito de arquitetura, não como camada adicional.

Criptografia

Dados em trânsito protegidos por TLS em todos os pontos de entrada; dados em repouso criptografados via KMS no S3, Aurora e nas filas — com rotação de chaves gerenciada.

Identidade e acesso

Autenticação de usuários e serviços via Amazon Cognito com MFA obrigatório; permissões de cada componente seguem IAM com o princípio de menor privilégio.

Trilha de auditoria

Todas as ações sobre dados e infraestrutura são registradas via AWS CloudTrail, correlacionadas ao identificador de documento para reconstrução completa de qualquer evento.

LGPD

Anonimização de dados pessoais fora do fluxo estritamente necessário, políticas de retenção configuráveis por categoria de documento e mecanismo de direito ao esquecimento sob demanda.

Segregação de ambientes

Contas ou VPCs separadas para desenvolvimento, homologação e produção, sem compartilhamento de dados reais fora do ambiente de produção.

Borda e detecção de ameaças

AWS WAF protegendo os endpoints públicos do gateway de ingestão e do Portal/API; Amazon GuardDuty monitorando comportamento anômalo em toda a conta.

06 · Escalabilidade

Escala com o volume, não com a antecipação

A arquitetura é serverless-first: cada componente escala de forma independente, sem capacidade fixa reservada para pico.

Compute sem servidor fixo

Lambda e Fargate escalam automaticamente conforme o volume de documentos recebidos — sem provisionamento antecipado de capacidade.

Filas absorvendo picos

SQS desacopla ingestão de processamento: picos de entrada são enfileirados e processados no ritmo que os agentes suportam, sem perda de documento.

Banco elástico

Aurora Serverless v2 ajusta a capacidade de computação sob demanda, sem downtime, acompanhando variações de carga de leitura e escrita.

Particionamento lógico

Dados particionados por categoria de produto e por rede varejista, permitindo isolamento de carga e evolução independente por segmento.

Processamento distribuído e desacoplado

Cada agente é uma unidade de execução independente, acionada por evento. Um agente sob carga alta não bloqueia os demais — o barramento de eventos e as filas absorvem a diferença de ritmo entre eles.

07 · Próximos passos técnicos

Para o time levar desta apresentação

Setup inicial

  • Conta AWS — organização, contas separadas por ambiente, billing alerts configurados
  • Baseline de IAM/VPC — papéis mínimos por componente, VPC e subnets definidas antes do primeiro deploy
  • Acesso ao Bedrock — habilitação do modelo Claude na região escolhida

Fundação de entrega

  • Provisionar IaC — repositório Terraform ou CDK com pipeline de CI/CD desde o primeiro commit
  • Observabilidade base — CloudWatch e X-Ray habilitados antes do primeiro agente entrar em produção
  • Iniciar Fase 1 — Gateway de Ingestão + Agente Classificador como primeiro fluxo ponta a ponta
